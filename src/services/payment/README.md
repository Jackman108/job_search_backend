# Платежная система

## Архитектура

Платежная система реализована в соответствии с принципами SOLID и функционального программирования. Основной паттерн проектирования - "Стратегия" (Strategy Pattern), который позволяет гибко переключаться между различными платежными провайдерами.

### Структура директорий

```
services/payment/
  ├── base/                  # Базовые компоненты платежной системы
  │   ├── paymentService.ts           # Общие функции для работы с платежами
  │   ├── paymentStrategyContext.ts   # Контекст стратегии платежей
  │   ├── paymentIntegrationService.ts # Интеграционный сервис для платежей
  │   ├── paymentErrorHandler.ts      # Обработчики ошибок для платежей
  │   ├── infoPaymentService.ts       # Сервис информации о платежах
  │   └── subscriptionsService.ts     # Работа с подписками
  │
  ├── webpay/                # Компоненты для работы с WebPay
  │   ├── webpayStrategy.ts           # Стратегия WebPay платежей
  │   ├── webpayIntegrationService.ts # Интеграция с API WebPay
  │   └── webpayService.ts            # Сервис для работы с WebPay платежами
  │
  └── crypto/                # Компоненты для работы с криптоплатежами
      ├── cryptoStrategy.ts           # Стратегия криптоплатежей
      ├── cryptoIntegrationService.ts # Интеграция с API криптоплатежей
      └── cryptoService.ts            # Сервис для работы с криптоплатежами
```

## Использование

### Интерфейсы

Все интерфейсы платежной системы определены в директории `interface/`:

- `payment.interfaces.ts` - базовые интерфейсы для всех платежей
- `webpay.interfaces.ts` - интерфейсы для WebPay платежей
- `crypto.interfaces.ts` - интерфейсы для криптоплатежей

### Контроллеры

Контроллеры для работы с платежами:

- `PaymentController.ts` - базовый контроллер для операций с платежами
- `PaymentIntegrationController.ts` - общий контроллер для инициализации платежей
- `WebpayController.ts` - контроллер для WebPay
- `CryptoPaymentController.ts` - контроллер для криптоплатежей
- `InfoPaymentController.ts` - контроллер для получения информации о платежах

### Маршруты

Маршруты для платежей:

- `payment.routes.ts` - базовые маршруты для работы с платежами
- `paymentIntegration.routes.ts` - общие маршруты для интеграции платежей
- `webpay.routes.ts` - маршруты для WebPay
- `crypto.routes.ts` - маршруты для криптоплатежей
- `infoPayment.routes.ts` - маршруты для получения информации о платежах

## Обработка ошибок

Система использует функциональный подход к обработке ошибок:

- `withErrorHandling` - утилита для обертывания асинхронных функций с обработкой ошибок
- `paymentErrorHandler.ts` - специализированные обработчики ошибок для платежных операций
- Контроллеры используют `try/catch` для перехвата и обработки исключений

## Расширение системы

Для добавления нового платежного провайдера необходимо:

1. Создать новый интерфейс в директории `interface/`
2. Реализовать стратегию платежей в соответствии с интерфейсом `PaymentStrategy`
3. Добавить интеграционный сервис для взаимодействия с API провайдера
4. Создать сервис для работы с платежами нового провайдера
5. Добавить контроллер и маршруты для нового провайдера
6. Добавить новый метод в список доступных методов в `payment.config.ts`

## Принципы проектирования

- **Единственная ответственность (SRP)**: Каждый модуль отвечает только за одну часть функциональности
- **Открытость/закрытость (OCP)**: Система легко расширяется без изменения существующего кода
- **Инверсия зависимостей (DIP)**: Высокоуровневые модули не зависят от низкоуровневых
- **Функциональный подход**: Предпочтение отдается функциям, а не классам
- **Обработка ошибок**: Централизованная обработка ошибок с использованием общих утилит

## Типизация

Система использует строгую типизацию TypeScript:

- `PaymentBase` - базовый интерфейс для всех платежей
- `PaymentResult<T>` - обобщенный интерфейс для результатов операций
- `PaymentStatus` - перечисление статусов платежа
- `PaymentStrategy` - интерфейс для реализации стратегий платежей
- `IPaymentService` - интерфейс для платежных сервисов
